# F-1 클라우드 악보 수동 검증

상태: **아래 외부 시나리오는 아직 실행하지 않았습니다.** 메인 에이전트가 SQL을 검토/적용한 뒤 결과를 기록해야 합니다. 구현 에이전트는 원격 DB를 변경하지 않았습니다.

사전 준비: 동일 프로젝트 공개 설정을 가진 앱, 회원 A/B(실제 로그인으로 생성한 계정), 기존 정책으로 지정된 관리자, 익명 브라우저 창을 준비합니다. `scoreforge_auth.sql` 다음에 `scoreforge_scores.sql`을 적용하고 재적용합니다. `private`가 API exposed schemas에 없는지 확인합니다. 기존 레슨 앱/프로필 권한은 그대로 유지합니다.

| 공유 중지/회전 | 공유 끄기 → 이전 URL 0행. 다시 켜기 → 새 slug, 이전 URL 계속 0행 | 미실행 |
| 읽기 전용 가드 | 공유에서 키보드/음표 입력/드래그/붙여넣기/속성/undo/redo/설정 편집 불가. 사본 만들기 후 편집 가능, cloud metadata와 share URL 제거 | 미실행 |
| 열기 실패 | 로컬 미저장 악보 편집 → 없는 private id 또는 중지/손상된 공유 열기 → 현재 악보/undo/읽기 전용 상태 유지 | 미실행 |
| 느린 저장 중 편집 | DevTools 느린 네트워크 → 저장 요청 중 추가 음표 → 응답 후 추가 편집 유지, 저장 완료로 오표시하지 않고 다음 요청으로 최신 내용 저장 | 미실행 |

| 충돌 덮어쓰기 | 충돌에서 덮어쓰기 선택 → owner/id 조건으로 명시적 강제 저장. 사용자 선택 전 강제 UPDATE 없음 | 미실행 |
| 충돌 사본 | 충돌에서 다른 이름으로 저장 → 새 private 행, 기존 원격 악보 그대로, 로컬 연결은 새 행 | 미실행 |

| 재시작 복구 | 오프라인 편집 후 새로고침 → 같은 계정/프로젝트 온라인 복귀 → 저장된 대기 내용 전송, 원래 INSERT UUID 재사용 | 미실행 |
| 계정 경쟁 | getUser/저장 응답 대기 중 로그아웃 또는 B로 전환 → A 대기 작업 B로 전송하지 않음, B 현재 악보 메타를 변경하지 않음 | 미실행 |
| 만료 세션 | UI에 로그인처럼 보여도 getUser가 거절되면 private 쿼리 없음, 로컬 내용/큐 유지 | 미실행 |
| undo | 저장 성공이 undo 항목을 추가하지 않음. 저장 후 undo/redo → 음악만 변경, cloud id 및 최신 서버 시각 유지 | 미실행 |
| 삭제 | 목록에서 확인 후 삭제 → 목록 갱신, 공유 0행, 현재 악보 내용은 로컬로 유지하며 cloud id 제거 | 미실행 |
| 크기/ACL | data 2MB 이상/비객체, 음수 measures, 빈/200자 초과 title, 잘못된 slug, owner/서버 시각 UPDATE 시도 → DB 거절 | 미실행 |
| 악성 제목 | `<img src=x onerror=alert(1)>` 제목 저장/목록/이름 변경/삭제 대화상자 → 일반 텍스트, 코드 실행 없음 | 미실행 |
| 회귀 | 데모 4곡 열기/재생, JSON 저장-열기, MusicXML 내보내기/가져오기, 기존 회원/관리자/레슨 앱 동작 | 미실행 |

SQL 확인은 `supabase/README.md`의 권한 조회, 실제 JWT로 RLS/API 요청, Supabase Security Advisor를 포함합니다. `SET ROLE anon`으로 direct table SELECT를 실행하면 의도적으로 트랜잭션이 오류 상태가 되므로 기대 오류 시나리오는 별도 트랜잭션에서 실행하세요. 테스트 데이터는 검증한 실제 계정의 id를 사용하고 사용자를 임의 생성하지 마세요.

로컬 자동 검증: `node --test tests/cloud.test.mjs`. 이는 Supabase client 응답/세션을 모의한 Node 테스트이며 실제 PostgreSQL 구문, RPC 권한, 네트워크, 브라우저 접근성 검증은 포함하지 않습니다. 최종 실행 수/결과는 `tmp/cloud-handoff.md`에 기록합니다.
